## 1. 좌표계 (2:1 아이소메트릭)

### 1.1 타일과 바닥
| 항목 | 값 |
|---|---|
| 타일(바닥 한 칸) | 마름모 **64×32 px** (가로:세로 = 2:1) |
| 바닥 | **8×8 타일**, 마름모 전체 512×256 px |
| 그리드 축 | `gx` = 오른쪽 아래로 증가, `gy` = 왼쪽 아래로 증가. 원점 (0,0)은 뒤쪽 꼭짓점 |
| 벽 | 뒤쪽 두 변에만 있다. 왼쪽 벽 = `gx = 0` 변, 오른쪽 벽 = `gy = 0` 변 |
| 벽 높이 | **160 px** (미니미 키의 약 2.1배) |

### 1.2 방 캔버스 (네이티브 해상도)
```
        ┌──────────────── 512 ────────────────┐
  y=8   ·            /\  ← 벽 꼭대기 뒤 모서리   ·
        ·   왼쪽 벽 /  \ 오른쪽 벽              ·
  y=168 ·          /\  /\   ← 바닥 뒤 꼭짓점 (원점)·
        ·         /  \/  \                      ·
        ·  바닥 8×8 마름모 (512×256)            ·
  y=424 ·          \    /   ← 바닥 앞 꼭짓점      ·
  y=432 └─ 바닥 두께 8px ──────────────────────┘
```
| 항목 | 값 |
|---|---|
| 캔버스 | **512 × 432 px** |
| 바닥 원점 (0,0)의 화면 좌표 | **(256, 168)** |
| 바닥 판 두께 | 8 px (앞쪽 두 변 아래) |

### 1.3 변환 공식
타일 꼭짓점 (gx, gy) → 캔버스 좌표:
```
x = 256 + (gx − gy) × 32
y = 168 + (gx + gy) × 16
```
캔버스 좌표 → 타일 (터치 판정, 소수점 버림):
```
gx = ((x − 256) / 32 + (y − 168) / 16) / 2
gy = ((y − 168) / 16 − (x − 256) / 32) / 2
```
타일 중심 = (gx + 0.5, gy + 0.5)를 변환한 점이다. 미니미의 발이 이 점에 놓인다.

### 1.4 확대 규칙 (픽셀 선명도)
픽셀 아트는 **물리 픽셀 기준 정수배**로만 확대한다. 논리 픽셀(pt/dp) 기준으로 맞추면 DPR 때문에 픽셀 크기가 들쭉날쭉해진다.

```
s = floor(방에 쓸 수 있는 물리 픽셀 폭 / 512), 최소 1
표시 크기(논리 px) = 512 × s / devicePixelRatio
```

| 기기 예 | 화면 폭(물리) | s | 방 폭(논리) |
|---|---|---|---|
| iPhone 15 (393pt @3x) | 1179 | 2 | 341pt (87%) |
| iPhone 15 Pro Max (430pt @3x) | 1290 | 2 | 341pt (79%) |
| Galaxy S23 (360dp @3x) | 1080 | 2 | 341dp (95%) |
| Pixel 7 (412dp @2.625) | 1081 | 2 | 390dp (95%) |
| QHD 폰 (412dp @3.5) | 1440 | 2 | 293dp (71%) |
| iPhone SE 3 (375pt @2x) | 750 | 1 → 규칙상 2 | 512pt, 좌우 스크롤 |

**결정 사항**
1. **방은 화면 폭 전체(좌우 여백 없이)를 쓴다.** 좌우에 20pt 여백을 두면 1080px 폰들에서 s=1이 되어 방이 171dp로 작아진다.
2. **s로 계산한 방 폭이 화면 폭의 70% 미만이면 s+1로 키우고 가로 스크롤을 허용한다.** (iPhone SE 등)
3. 이미지는 `FilterQuality.none`으로 그리고, 모든 위치를 네이티브 정수 픽셀로 반올림한다.
4. 남는 공간은 방 배경색(`#F6EBDD`)으로 채운다. 늘리거나 잘라 맞추지 않는다.
5. 확대·축소(핀치)를 넣는다면 정수 단계(s, s+1)로만 한다.

## 3. 스프라이트 규격

### 3.1 바닥 가구
점유 w×d 타일, 물체 높이 h일 때:
```
스프라이트 폭  = (w + d) × 32
스프라이트 높이 = (w + d) × 16 + h   → 8의 배수로 올림
앵커(anchor)   = (d × 32,  높이 − (w + d) × 16)
               = 점유 영역의 '뒤쪽 꼭짓점'이 스프라이트 안에서 놓이는 위치
그리는 위치    = isoToScreen(gx, gy) − anchor
```

MVP 가구 5종 규격:
| assetId (기존 id) | w×d | h | 스프라이트 | 앵커 |
|---|---|---|---|---|
| `bed_single` | 1×2 | 52 | **96×104** | (64, 56) |
| `desk_wood` | 2×1 | 64 | **96×112** | (32, 64) |
| `chair_wood` | 1×1 | 48 | **64×80** | (32, 48) |
| `lamp_stand` | 1×1 | 104 | **64×136** | (32, 104) |
| `plant_small` | 1×1 | 36 | **64×72** | (32, 40) |
| `rug_round` | 2×2 | 0 | **128×64** | (64, 0) |

### 3.2 회전
- 방향은 2개다. **R0**는 앞면이 왼쪽 아래를 본다. **R1**은 앞면이 오른쪽 아래를 보고, w와 d가 서로 바뀐다.
- 광원이 왼쪽 위로 고정이라 **좌우 반전하면 명암이 뒤집힌다.** 그래서 회전 가능한 가구는 **R1을 따로 그린다**(`*_r1.png`).
- R1이 없는 가구는 `rotatable: false`로 두고 R0만 쓴다.
- 예외: 평평한 벽 장식(액자·포스터)과 러그는 반전을 허용한다(명암 차이가 거의 없음).

### 3.3 벽 장식
- 좌표: `wall` (L|R), `u` (벽을 따라 몇 번째 칸, 0~7), `z` (바닥에서 아래 변까지 높이, px), 폭 `w` 칸.
- 스프라이트: 폭 `w × 32`, 높이 `w × 16 + h`. 왼쪽 벽용으로 그리고, 오른쪽 벽은 반전한다.
- 벽 장식은 바닥 가구와 **겹침 판정을 하지 않는다**. 같은 벽 안에서만 칸 겹침을 막는다.

### 3.4 바닥·벽 타일
| 에셋 | 규격 | 비고 |
|---|---|---|
| 바닥 타일 | 64×32 마름모 | 이웃 타일과 이음매 없이 이어져야 함 |
| 벽 조각 (왼쪽 벽 1칸) | 32×176 (벽 160 + 기울기 16) | 오른쪽 벽은 반전 + 한 단계 어둡게(§5 광원) |
| 걸레받이 | 벽 조각에 포함, 아래 8px | |

### 3.5 PNG 규칙
- RGBA PNG, 배경 투명.
- **알파는 0 또는 255만 쓴다.** 반투명이 필요한 그림자는 엔진이 그린다.
- 색은 §6 팔레트 안에서만 쓴다.
- 파일 크기(가로·세로)는 위 공식과 **정확히** 같아야 한다. 자동 검증으로 확인한다(PART 5).

## 4. 깊이 정렬

그리는 층 (뒤 → 앞):
1. **바닥 층**: 바닥 타일 → 러그 같은 바닥 장식 → 엔진 그림자
2. **벽 층**: 벽 → 벽 장식 (벽은 항상 모든 바닥 물체보다 뒤에 있다)
3. **물체 층**: 바닥 가구 + 미니미를 아이소메트릭 순서로 그린다
4. **UI 층**: 선택 테두리, 배치 가능/불가 표시

물체 층 순서 (점유 영역이 겹치지 않는 직사각형끼리):
- A의 앞쪽 끝이 B보다 앞이면, 즉 `A.gx ≥ B.gx + B.w` 또는 `A.gy ≥ B.gy + B.d`이면 **A를 B보다 나중에** 그린다.
- 이 관계로 위상 정렬하고, 같은 순위면 `(gx + gy)` → `id` 순으로 고정한다.
- 미니미는 1×1 물체로 다룬다. 걷는 중이면 들어가는 타일 기준으로 판정한다.

**엔진이 그리는 그림자**
- 모든 바닥 가구와 미니미 밑에, 점유 마름모를 1px 안쪽으로 줄인 모양을 그린다.
- 색 `#6B4F3A`, 불투명도 28%.
- 스프라이트에 그림자를 직접 그려 넣지 않는다. 이렇게 해야 모든 에셋의 그림자가 똑같아진다.

## 5. 광원과 명암

- **광원: 왼쪽 위** (방의 왼쪽 벽 창문 쪽).
- 면별 밝기:
  - 윗면 = 하이라이트 또는 기본색
  - 왼쪽을 향한 면 = 기본색
  - 오른쪽을 향한 면 = 그늘색
  - 가장 깊은 틈 = 짙은색
- 재질마다 **3~4단계 램프**를 쓴다(§6). 단계를 건너뛰는 그라데이션, 필터, 노이즈는 쓰지 않는다.
- 하이라이트는 왼쪽 위 모서리에 1px 선이나 점으로만 넣는다.
- 디더링은 넓은 면(벽지·바닥 무늬)에서만, 2색 체커 패턴으로 제한한다. 캐릭터에는 쓰지 않는다.
- 벽: 왼쪽 벽은 기본색, 오른쪽 벽은 한 단계 어둡게 칠한다.

## 7. 외곽선과 선

- **1px 외곽선.** 순수한 검정(`#000`)은 쓰지 않는다.
  - 캐릭터: 잉크 `#4A3628`
  - 가구: 그 재질 램프의 가장 짙은 색(셀아웃)
- 안쪽 선은 그늘색 1px.
- 아이소메트릭 사선은 **가로 2px : 세로 1px 계단**으로만 긋는다(2:1 선). 1:1이나 불규칙한 계단은 쓰지 않는다.
- 같은 물체 안에서 픽셀 크기가 섞이면 안 된다(2×2 덩어리 금지).

## 8. 미니미

### 8.1 프레임과 비율
| 항목 | 값 |
|---|---|
| 프레임 | **64×96 px** |
| 앵커 | **(32, 88)** = 발 가운데. 타일 중심에 맞춘다 |
| 그림 영역 | x 12~52, y 4~88. 머리 장식은 y 4까지 쓸 수 있다 |
| 키 | 76 px (y 12~88) |
| 머리(머리카락 포함) | 34 px → **약 2.2등신** |
| 몸통 + 다리 | 42 px |
| 얼굴 | 눈 2×3 px(잉크), 볼 3×1 px(테라코타 밝음), 입은 생략하거나 2px |

### 8.2 방향 (2026-11-11 승인: 정면 + 측면 반전)
초기 제작 비용을 줄이려고 **두 방향만 그린다.**

| 방향 | 쓰는 때 | 제작 |
|---|---|---|
| 정면 (카메라를 봄) | 서 있을 때, 보상을 받을 때 | 그린다 |
| 측면 오른쪽 | 화면 오른쪽으로 움직일 때 (화면 위쪽으로 갈 때 포함) | 그린다 |
| 측면 왼쪽 | 화면 왼쪽으로 움직일 때 | 측면 오른쪽을 좌우 반전 |
| 뒷모습 | — | **만들지 않는다.** 필요한 기능이 생기면 별도 검토 |

- 좌우가 다른 레이어(옆 머리핀 등)는 `mirror: false`로 표시하고, 측면 왼쪽용을 따로 그린다.
- 고르는 규칙은 03 §6에 있다.

### 8.3 애니메이션
| 이름 | 프레임 | 속도 | 내용 |
|---|---|---|---|
| idle | 4 | 4 fps | 2·3번 프레임에서 몸이 1px 내려감. 4번 프레임에 눈 깜박임 |
| walk (나중) | 6 | 10 fps | 측면만. 발 교차. 머리 위아래 움직임은 1px 이내 |

- 스프라이트 시트: 가로 = 프레임, 세로 = 방향(정면, 측면).
  - idle 시트: 256×192
  - walk 시트: 384×96 (측면 한 줄)
- **모든 레이어 시트는 크기·프레임 수·앵커가 같아야 한다.**

## 10. AI 생성 이미지를 실제 에셋으로 만드는 방법 (핵심 질문 4)

AI 이미지 생성기는 **2:1 각도, 픽셀 격자, 팔레트, 크기를 정확히 지키지 못한다.** 그래서 생성 결과는 **초안**으로만 쓰고, 최종 에셋은 아래 단계를 거친다.

1. **템플릿 먼저**: 점유 크기별 마름모 가이드 PNG(1×1, 1×2, 2×1, 2×2 …)와 미니미 64×96 실루엣 가이드를 만든다. 사람이나 도구가 이 위에 맞춘다(PART 5에서 생성 스크립트 작성).
2. **생성**: §9 프롬프트로 목표 크기의 4~8배로 생성한다. 픽셀 아트 전용 도구(아이소메트릭이나 스프라이트 시트를 지원하는 것)가 있으면 우선 검토한다. 도구 선택은 PART 5에서 비교한다.
3. **축소**: 최근접 이웃(nearest) 방식으로 목표 크기까지 줄인다. 격자가 어긋나면 원래 픽셀 크기를 찾아 맞춘다.
4. **팔레트 맞춤**: §6의 57색으로 강제로 바꾼다(디더링 없이).
5. **손 보정 (필수)**: Aseprite 같은 픽셀 편집기에서 사람이 다듬는다.
   - 2:1 선 정리, 외곽선, 명암 단계
   - 앵커 맞추기, 점유 범위 밖으로 나간 픽셀 지우기
   - 반투명 픽셀 제거
6. **자동 검증**: 크기, 알파(0/255), 팔레트 밖 색, 점유 범위 침범, 레이어 시트 크기 일치를 확인한다(PART 5에서 테스트로 구현).
7. **사람 검수**: 기준 장면에 넣어 실제 크기로 나란히 놓고 본다. 통과한 것만 `final`로 등록한다.

현실적인 판단:
- 일관성이 가장 중요한 **미니미 기본 몸, 바닥, 벽, 기준 가구 5종은 사람이 직접 그리거나 크게 보정**해야 한다.
- AI는 가구 변형(색·무늬 바꾸기), 소품 아이디어, 초안에서 시간을 줄여 준다.
- 외부 픽셀 아티스트에게 맡기거나 라이선스가 확인된 에셋 팩을 쓰는 것도 대안이다. 이 경우에도 이 가이드의 규격과 팔레트를 따르게 한다.

## 11. 기존 상점·보상·저장 구조와의 연결 (핵심 질문 5)

| 기존 | 연결 방식 |
|---|---|
| `ShopItem.id` | 그대로 **assetId**. 이름을 바꾸지 않는다(저장 데이터 호환) |
| 가격·레벨·종류 (`shopCatalog`) | 그대로 Dart 코드에 둔다. **보상 정책은 바꾸지 않는다** |
| 그림 정보 | `assets/pixel/manifest.json`에 id별로 둔다. 경로, 크기, 앵커, 점유 w×d, 회전 가능, 층, 레이어(옷), 상태(`draft`/`final`). 테스트가 모든 상점 아이템에 매니페스트 항목과 파일이 있는지, 크기가 맞는지 확인한다 |
| `ShopItem.assetPath` | 매니페스트로 옮기고 필드는 정리한다(PART 2에서 결정) |
| `RoomSlot` | '자리' 대신 **분류**(침대·책상·조명…)로 쓴다. 상점 분류와 보관함 필터는 그대로 유지 |
| `Profile.placed` | 남겨 두고 읽기만 한다. 새 필드 `room`이 없으면 `placed`의 자리마다 기본 타일 위치를 줘서 만든다(**기존 데이터 손상 없음**) |
| `Profile.room` (신규) | 바닥 `{id: {x, y, r}}` · 벽 `{id: {w, u, z}}` · 벽지·바닥재 · 미니미 위치. 키가 아이템 id라 같은 분류 여러 개 가능 (02 §5) |
| `Minimi` 색 인덱스 | 팔레트 스왑 인덱스로 사용 |
| `outfitId`·`accessoryId` | 그대로. 옷·액세서리 레이어를 고르는 키로 쓴다 |
| 벡터 painter | 에셋이 없거나 `draft`일 때의 대체 그림과 테스트용으로 남긴다 |
